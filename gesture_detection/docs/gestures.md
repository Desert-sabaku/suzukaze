# ジェスチャー仕様

この文書を、アプリケーションが現在判定するジェスチャー仕様の正本とします。
しきい値の実値は `src/gesture_detection/config.py`、判定処理は `src/gesture_detection/recognition.py`
（優先順位の調停）、`src/gesture_detection/hand_gesture.py`（扇ぎ）、`src/gesture_detection/relaxing.py`、`src/gesture_detection/bow.py`、
`src/gesture_detection/uchimizu.py`、`src/gesture_detection/ramune.py` にあります。
ここに記載する値は現在のヒューリスティックに基づくもので、認識精度を保証しません。

## 共通条件と優先順位

MediaPipe Pose の1人目のランドマークを使用します。通常は可視度が `0.5` を超える
必要点だけを有効とします。時間条件には、処理時間ではなく入力元の時刻を使います。

ラムネの準備・開栓を最優先し、その間は片手ジェスチャーをリセットします。
片手では打ち水を扇ぎより優先します。ただし、直近1秒に十分な振幅の方向反転が
3回以上ある扇ぎは、打ち水の準備中でも優先できます。どの主要動作も選ばれていない
場合は礼を夕涼みより優先し、そのどちらでもなければ夕涼みを表示します。

## 礼

腰から上体を前に曲げ、画像上の上体角度が20〜75度の姿勢を0.25秒保つと成立します。
両腰の中心から両肩の中心への方向と、同じ腰の中心から鼻への方向の差が40度以内で、
鼻が肩よりも上体を倒す方向へ出ていることを確認します。上体が直立したままの
首だけのお辞儀は除外します。方向差は首の関節角度ではなく、投影された上体と頭の
位置関係です。鼻が肩より下に来る深い礼も判定対象です。
両肩・両腰が画面内にあることを確認します。鼻は深い礼でカメラの横へはみ出すため、
画面端から画面幅・高さの0.1倍の外側まで許容します。可視度の下限は両肩・両腰が`0.5`、
斜め方向で部分的に隠れる鼻が`0.35`です。姿勢を戻すか追跡を失うと解除します。
画像上の角度を用いるため、横〜斜めから胴体の傾きが見えるカメラ配置が必要です。
足元から1.5〜2m先を見るのは実演時の目安であり、視線そのものは判定しません。
カメラのプレビューには `Bow` の測定角度（0〜90度のバー、緑の範囲が20〜75度）と
成立までの保持時間（下のバー）を表示します。正面からだと実際に曲げても表示角度が
小さくなりやすいため、横〜斜めにカメラを置き、腰まで画面に入れます。
腰の位置を誤って推定した場合や、画面外に推定した場合は成立しません。モデルが誤った骨格を
返した場合の判定は保証できないため、必要な点の位置を骨格表示で確認してください。

## 夕涼み

入力元の時刻で、全身が連続1秒間静止すると成立します。鼻、肩、肘、手首、腰、膝、
足首、かかと、つま先のうち画面内で追跡できる点を監視し、両肩と両腰は必須です。
見えていない部位を静止とはみなしません。追跡対象となる部位の組み合わせが変わると、
静止時間を最初から測り直します。

移動量は平均ではなく、監視点のうち最大の値を使います。画像上の座標をそのまま使う
ため、全身の平行移動、傾き、カメラへの接近も動きになります。横方向は画像の縦横比を
補正し、距離は肩から腰までの長さで正規化します。

次のいずれかを超えた最初の処理フレームで解除します。再成立には改めて1秒の静止が必要です。

- 速度: 胴体長の `0.40` 倍/秒
- 固定した静止開始位置からの変位: 胴体長の `0.055` 倍

両肩・両腰の欠落、追跡部位の変化、増加しない時刻、`0.25` 秒を超えるフレーム間隔でも
解除します。画面外の足は評価できず、カメラの移動も身体の移動として扱われます。
ここでいう即時解除は、動きを検出した最初の処理フレームでの解除であり、表示遅延が
ゼロという意味ではありません。

## 打ち水

左右どちらかの手首を胴体前方の低い位置から持ち上げ、すくう準備をした後、下げて
水を放つ動作を判定します。放つときの横移動は任意です。鼻、両肩、両腰、動かす手首が
見えている必要があります。

1. 肩から腰までの長さを1とし、肩から `0.55` 以上低い位置を起点にする。
2. `1.2` 秒以内に手首を `0.10` 以上持ち上げる。
3. 最高点から `1.5` 秒以内に `0.15` 以上下げ、肩から `0.50` 以上低い位置で終える。

準備の開始時は顔から離れ、胴体の横幅に肩幅の `0.25` 倍を加えた範囲内に手首を置きます。
準備中に手首が顔に近づいても、肩より下にあれば準備を続けます。カメラが近いと、
胸の高さですくうだけで顔に近く映るためです。肩より上で顔に近づくと準備を破棄します。
最高点を更新すると、放すための時間枠も更新します。そのため、頂点で短く停止できます。追跡を
失うか時間切れになると準備を破棄します。成功表示は `0.35` 秒、新たな動作を受け付ける
までのクールダウンは成功時から `0.6` 秒です。

## 扇ぎ

手首が胴体上半分付近にある状態で、手の周期運動を判定します。動きは手首・小指・
人差し指の平均位置で測るため、手首をほぼ止めて手のひらだけを振る扇ぎも対象です。
横方向は画像の縦横比を補正し、直近1秒で最も大きく動いた方向の成分を使います。
縦置きカメラで横向きに見える扇ぎも、上下の扇ぎと同じ基準で判定します。
直近1秒を時刻で等間隔に再標本化し、`1–3 Hz` の周波数成分、振幅、直近速度から
スコアを計算します。
姿勢を `0.2` 秒保った後、スコアのしきい値とヒステリシスにより成立・解除します。

胴体中央より下への逸脱は `0.35` 秒まで許容します。肩から腰までの `0.75` を超えて
手首を下げると直ちに姿勢を解除し、中央より下に許容時間を超えて留まった場合も解除します。

打ち水の準備中と成功後1秒間は、単発の扇ぎスコアを採用しません。これはすくって放す
1往復が扇ぎに見えるのを防ぐためです。一方、直近1秒に `0.08` 以上の上下反転が3回以上
ある継続的な扇ぎは、この抑制を解除して優先できます。

## ラムネ開栓

1. 片手で瓶口を表す輪を作り、胴体の前に置く。
2. もう片方の手を上に置き、`0.25` 秒保つ。
3. 下の手を保ったまま、構えが成立してから`3.0` 秒以内に上の手を押し下げる。
4. 成功表示を `0.8` 秒続ける。再実行には上の手を離して準備をやり直す。

構え成立後も、許容する準備範囲内で上の手をさらに持ち上げた場合は、押し込みの
開始位置をその最新位置へ更新し、待ち時間もその時点から測り直します。
単眼・2カメラのルール判定で共通です。すでに待ち時間を超えた構えは復活させません。

構えが成立した後は、上の手を助走としてさらに高く上げることもできます。
通常の上下間隔の上限`0.90`（肩幅単位）を超えてから、最大`1.0`秒以内に
押し下げへ移る必要があります。助走中は上下間隔`1.50`まで許容し、上昇を続けても
助走の時計は延長しません。上の手が`0.25`以上下がり、両手の間隔も`0.25`以上
縮むと助走を終え、通常の押し込み判定へ移ります。最初から高く離した手では
準備は成立せず、助走中も下の手の移動許容・追跡条件は必要です。

指の形は利用者への指示であり、判定対象ではありません。両手首の位置と移動順序を使い、
左右どちらの手も上下の役割を担当できます。両手を一緒に下げる、横へ動かす、準備なしで
接触させる動作は成立しません。両手首、両肩、両腰が見えなくなると準備を破棄します。

縦横の距離を画像の縦横比で補正してから肩幅で正規化します。準備中の左右の手の横ずれは `1.0` まで許容し、
開栓成立時は `0.60` 以内に収まる必要があります。広い構えのまま押しても開栓せず、
タイムアウトまでに横位置が収まれば通常の押し込み条件で判定します。
横ずれが`0.60`以内の両手の構えは、打ち水の準備候補と重なってもラムネの保持時間を測り続けます。
打ち水の振り下ろしが成立した場合や、両手の横ずれが大きい準備候補では打ち水を優先します。
下の手が初期位置からずれても、横 `0.75`・縦 `0.50` まで許容します。下の手が多少動いても構えを維持しますが、
両手が同じだけ下がる動作や、下の手だけが上がる動作では開栓しません。
準備時の上下間隔は `0.30–0.90`、終了時は
`0.30` 以内です。上の手が `0.25` 以上下降し、準備完了時から上下間隔も `0.25` 以上
縮まった場合だけ開栓とします。

画面下部には準備、押下、成功、再試行の案内を表示します。OpenCV の既存フォントを使う
ため、アプリケーション内の案内文は英語です。表示例は
[ラムネ案内画像](../shared/results/docs-assets/ramune-guide.png)を参照してください。この画像はUI例であり、認識精度を
示すものではありません。

## 所作の正確性（`action_accuracy`）

上記の所作条件に対する一致度を0〜1で返します。分類の確信度ではありません。
算出は `action_accuracy.py` と各イベント判定器が担当し、しきい値は `config.py` を参照します。
APIの省略・値域の契約は [`proto/README.md`](../../proto/README.md) が正本です。

### 項目点と集計

- 下限 `L` の条件: `clip(x / L, 0, 1)`。
- 上限 `U` の条件: `x <= U` なら1、超過時は `clip(2 - x / U, 0, 1)`。
- 許容区間 `[L, U]`: 上記2点の小さい方。区間全体が満点であり、中央値を理想値とはしません。
- 位置関係などの真偽条件: 満たせば1、満たさなければ0。
- 下表の各項目を**等重みの算術平均**で集計します。`clip` は0〜1への切り詰めです。
- 必要な測定が欠ける、または非有限値を含む場合は未評価です。欠測項目を0点にしたり、
  残りの項目だけで再平均したりしません。

| 所作 | 評価区間と項目（各項目が1票） |
| --- | --- |
| 礼 | 現在の上体角度、頭との方向差、頭の整列条件、連続保持時間の4項目 |
| 夕涼み | 最新の最大速度、静止開始位置からの最大変位、連続静止時間の3項目。可視点・追跡変更時のリセットは認識と共通 |
| 扇ぎ | 直近1秒の手首高さ履歴から、胴体上半分以内の時間割合、最大高さと最小高さの差（下限0.08）、周期（1〜3 Hz）、履歴の継続時間（下限0.2秒）の4項目 |
| 打ち水 | 準備開始位置の低さ、準備上昇量、上昇時間、準備時の胴体範囲内条件、顔から離れている条件、放つ終了位置の低さ、頂点からの下降量、頂点からの時間の8項目 |
| ラムネ | 構え保持時間、構えの上下間隔、構えの横ずれ、胴体内条件、上の手の下降量、上下間隔の縮小量、終了時の上下間隔、終了時の横ずれ、下の手の横変位・縦変位、押下時間の11項目 |

扇ぎの周期は、高さ0.08以上の方向反転数を `2 × 観測秒数` で割った有限窓での推定値です。
FFTの分類スコアは流用しません。位置の時間割合は各観測値を次の観測まで保持して積分します。
有効な肩・腰・手首の履歴が0.6秒以上必要で、0.25秒超の観測間隔や非増加時刻を含む間は未評価です。
姿勢逸脱の猶予や認識ヒステリシス中には、認識中でも部分点になり得ます。

打ち水の準備起点は、有効な上昇時間枠内で条件を満たす最も低い観測位置です。
ラムネの押下起点・時間枠は、上記の持ち上げ直し・助走規則に従います。
準備の破棄・追跡喪失・時間切れでは判定器の履歴もリセットされ、新しい動作に持ち越しません。
2カメラ用の打ち水でも画像座標での追加成立条件を通ったイベントだけを配信します。

### 公開する時点

- `State`: 代表所作が礼・夕涼み・扇ぎのとき、その観測の点数を公開します。
  `NONE`、追跡喪失、状態の期限切れでは省略します。
- `Event`: 打ち水・ルール型ラムネの成立時に、準備時の実測項目と成立時の実測項目から
  点数を確定します。成功表示の継続やイベント再送で再計算しません。
- 現行の礼・夕涼み・ルール型イベントは、成立条件と採点の満点条件が一致するため、
  成立時には通常1.0です。これは実測条件を満たした結果です。成立済み動作の中に
  さらに優劣を付けるには、別途、正本に品質の目標値を定義する必要があります。
- 未成立動作の点数は現行のState/Eventには公開しません。学習型ラムネは必要な
  ルール測定履歴を持たないため未評価とし、分類確率で代用しません。
- 複数カメラのStateは選ばれた所作の最新観測の点数を使います。点数が高いカメラを
  選ぶことはしません。Eventは重複除去で最初に採用したイベントの点数・有無を維持します。
- 指の輪・視線・画面外の部位は評価対象外です。異なる所作の点数は共通尺度ではありません。
