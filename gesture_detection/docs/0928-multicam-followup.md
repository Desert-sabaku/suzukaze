# 0928：配置・素材を変えない追加検証

実演条件の補足：ラムネ・夕涼みはphase説明UIなしでの実演。
両所作の追加改善は保留し、[引き継ぎ資料](0928-multicam-handoff.md)に採否と再現手順をまとめた。

**評価基準の更新：** [phase許容幅・action連続性の続報](0928-multicam-temporal.md)では、
ユーザーの注釈方針に合わせphase境界の±1秒を許容しています。
以下で厳密なOPENED区間外として扱ったcamera1の約0.43秒遅れの1件は、
新基準では検出成功です。本稿の厳密なphase採点は当時の診断記録として残します。

## 結論

**現時点では、撮り直しやカメラ移動を先に行う必要はない。既存映像でソフトウェア側の
課題をさらに切り分けられ、camera2の人物領域修正には効果があった。**
ただし、今回の調整だけで安定した4所作認識が成立したわけではない。

- camera2の人物領域を左寄りに広げると、骨格受け渡し率は5.0%から63.6%、
  扇ぎは0/3から3/3、打ち水は0/3から1/3になった。
- camera1では同じ方針で広げても扇ぎ・打ち水の検出試行数が減った。
  両カメラへ一律に広い領域を適用する変更は採用できない。
- ラムネはcamera1の領域変更で1件反応したが、OPENED注釈開始から約0.43秒後、
  OPENED区間外の発火だった。正しいタイミングでの開栓検出は依然0/3。
- ラムネの見逃しは、準備保持中のタイムアウト、下側の手の移動、手の横ずれ、
  押し込み量と両手の接近量が同時に成立しないことに分解できた。
- 夕涼みは固定の時間平滑化でcamera2の表示持続が伸びる例があったが、
  他所作中にも夕涼み表示が出た。単純な平滑化だけの採用は見送る。
- 学習済みラムネへ全画面の骨格を渡しても正解の開栓検出は0/3。
  マスクの修正だけでは、今回の画角に対するphase判定の不一致を解消できない。

前段：[一次検証](0928-multicam.md)。
生データ：[領域比較と判定診断](../shared/results/0928-multicam-followup-results.json)、
[表示持続時間と平滑化](../shared/results/0928-multicam-persistence.json)。

## 実験条件

素材・物理配置・動画の注釈は一次検証と同じ。推論の時計も一次検証の
`frame_id × session.duration / frame_count` を引き継いだ。
追加撮影・学習は行っていない。

### カメラ別の人物領域

代表画像の実演者位置から、次の領域を一度設定し、検出数を見て探索し直していない。
座標は画像幅・高さを1とした `(left, top, right, bottom)`。

| 設定 | 領域 |
| --- | --- |
| 従来共通 | `(0.35, 0.15, 0.75, 0.90)` |
| camera1候補 | `(0.20, 0.00, 0.95, 1.00)` |
| camera2候補 | `(0.00, 0.00, 0.70, 1.00)` |

この領域は既存人物選択の胴体中心条件と、探索時の横方向マスクに適用した。
胴体の可視性・サイズ・追跡条件、所作の判定しきい値は既存値を使った。
初期マスクが変わると、その後のMediaPipeの追跡結果も変わりうる。
したがって、これは単に推定済み骨格を領域で選別した実験ではない。

`rules_camera_roi` はこの条件で26動画・5,586フレームを追加推論した結果。
変更は評価スクリプト内だけに適用した。

### 学習済み判定への全画面骨格入力

一次検証の `rules_full` の骨格を、凍結した学習済みラムネ判定器へ入力した
`learned_full` を追加した。モデルや準備待ち条件は変更していない。
マスク外を含む骨格なので、学習時の入力条件とは異なる診断実験である。

夕涼み・扇ぎは1フレーム以上表示があった場合なので、持続時間も後述する。

| カメラ・条件 | 骨格受け渡し率 | 扇ぎ | 打ち水 | ラムネ action内 | 夕涼み |
| --- | ---: | ---: | ---: | ---: | ---: |
| camera1 従来領域 | 46.4% | 3/3 | 2/3 | 0/3 | 0/3 |
| camera1 候補領域 | 51.9% | 2/3 | 1/3 | 1/3※ | 0/3 |
| camera2 従来領域 | 5.0% | 0/3 | 0/3 | 0/3 | 0/3 |

注釈開始から13フレーム、約0.43秒遅く、注釈終端フレームから約0.20秒後。
OPENED区間内イベントという厳密な指標では0/3のまま。

候補領域で打ち水に反応した試行はcamera1が`001807`、camera2が`001754`。
相互補完はあるが、全画面で拾えていた`001817`を両カメラとも落とす。

全画面のcamera1 23件・camera2 9件より少ない一方、従来領域の2件・1件を
改善したわけではない。未注釈部分を含むため、これは誤反応候補の数である。

## ラムネ：どこで失敗しているか

ルール判定器の更新前に基準手位置・手の間隔・押し込み量などを記録し、
更新後の状態遷移と照合した。以下は代表的な観測。
複数条件が同時に不成立になることがあるため、記録された条件を
それぞれ独立した唯一の原因とは解釈しない。

### `001828`：押し始める前に準備が失効

- camera1全画面・候補領域とも、158フレームでREADYからIDLEへタイムアウト。
  OPENED注釈は163フレームからで、その直前に準備が失効している。
- READY中の押し込み量は、両条件とも必要量0.25肩幅へ一度も到達しない。
  準備成立時の上の手の位置より上側に留まっている。
- camera2は53フレームで下側の手の縦変位が許容値を超えてREADYを解除。
  全画面で0.367肩幅、候補領域で0.313肩幅、許容値は0.30。
  OPENED注釈は57フレームから。

準備の検出時刻と、実演の構え直し・上の手の持ち上げ方が判定条件と合っていない可能性がある。
タイムアウトだけを延ばせばよいという結果ではなく、押し込みの基準位置も課題。

### `001839`：片視点では遅延、もう一方では押し込み不足

- camera1全画面ではREADYに到達しないが、候補領域ではREADYを経て169フレームで発火。
  前述のとおり、注釈されたOPENED区間には間に合わない。
- camera2は両条件とも53フレームでREADYタイムアウト。
  全画面では手の接近・接触条件が成立する時点でも押し込み量が約0.114肩幅で、
  必要な0.25肩幅に届いていない。

### `001851`：手の上下動と接近量が同時に成立しない

- camera1では手の横ずれなどによりFORMINGが繰り返し解除され、READYへ到達しない。
- camera2では押し込み量の条件が成立するフレームがあるが、
  同時に必要な接近量・接触条件が揃わず、47フレームでタイムアウト。
- 候補領域ではタイムアウト時に押し込み0.340肩幅、接近0.239肩幅、
  残り間隔0.371肩幅。必要条件はそれぞれ0.25以上・0.25以上・絶対値0.30以下。

この映像には下側の手の移動、手首の推定位置の変動、投影方向の差が混在する。
骨格だけから手の接触や実際の押し込みの成否を断定しない。

## 学習済みモデル：マスクを外しても開栓は改善しない

全画面骨格を入力した `learned_full` でも、両カメラのラムネ検出は0/3。
ラムネactionに対応しないイベントはcamera1で3件、camera2で2件あった。

phase・準備待ちの内訳も、単なる準備条件の厳しさでは説明できない。

- camera1 `001828`：actionの105フレーム中100フレームをOPENEDと予測するが、
  準備のFORMING/READYを経ないため、全フレームWAIT_SETUP。
- camera2 `001828`：準備待ちを通過してARMEDになるが、その後OPENED予測が出ない。
  action内の唯一のOPENED予測は準備成立より前。
- camera2 `001839` と `001851`：ARMEDまで進んでも、action内のOPENED予測が0フレーム。

**準備待ちを外すと解決するとはいえない。** 開栓の前からOPENEDと誤分類している場合と、
開栓時にもREADYのままの場合がある。今回の視点で使う特徴量・モデルの検証が必要。

## 夕涼み：推定点の変動と時間平滑化

### 速度超過を起こす点

camera1全画面の夕涼み3試行では、主な最大速度点は肩・肘・手首だった。
例えば`001913`の142フレームでは、右肘62・右肩33・右手首26フレームが
各フレームの最大速度点となり、全142フレームで速度しきい値超過。
鼻だけを判定から除くような修正では解決しない。

骨格オーバーレイでは、画面外の顔に対応する鼻が首・胸の付近に推定されるフレームや、
身体の見え方に合わない肩・肘位置も確認した。
関節の正解座標は未注釈なので、位置誤差の数値評価までは行っていない。

### 固定0.15秒の因果的EMA

既存の時間ベース平滑化を実験用に転用し、時定数を0.15秒に固定。
未来フレームを使わず、欠落でリセットし、visibilityはそのまま使う。
平滑化した座標は夕涼み判定だけに渡し、速度・変位・1秒静止のしきい値は変更しない。
他所作の判定・イベントは凍結した結果を維持した。

camera2の夕涼み表示持続時間：

| 入力 | `001913` 合計 / 最長連続 | `001925` 合計 / 最長連続 |
| --- | ---: | ---: |
| 全画面 | 0.20 / 0.10秒 | 0 / 0秒 |
| 全画面＋平滑化 | 2.58 / 2.38秒 | 0.10 / 0.10秒 |
| 候補領域 | 0.69 / 0.40秒 | 0.30 / 0.30秒 |
| 候補領域＋平滑化 | 1.98 / 1.29秒 | 1.00 / 1.00秒 |

`001901`はすべて0、camera1もすべて0/3のままだった。
候補領域＋平滑化では、夕涼み以外のaction中のRELAXING表示が
camera1で約0.067秒、camera2で約0.399秒、新たに生じた。
平滑化による改善余地はあるが、他所作の準備・静止を夕涼みと誤認する課題が残る。

## 次の判断

1. **配置・素材は現状維持でよい。** 当面は既存映像の判定ロジック・入力条件の診断を続けられる。
2. camera2の領域修正を次の比較の候補にする。camera1は今回の広い候補を一律採用しない。
3. ラムネは準備開始・上の手の持ち上げ・押し込みの基準更新を分けて扱う候補を検証する。
   単なるしきい値緩和より、状態遷移と手の相対運動の見直しを優先する。
4. 夕涼みは表示の瞬間的な有無ではなく、持続率・解除遅延・他所作中の誤反応を評価する。
5. 統合は単純ORを採用せず、カメラ別の品質と所作別の誤反応を踏まえて比較する。

今回の素材を繰り返し使うため、改善値はこの撮影条件上の探索結果である。
最終的な汎化・ライブ性能の確認には独立した素材が必要になるが、今すぐ撮り直す必要はない。
