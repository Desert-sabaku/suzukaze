# 0924 action / phase 注釈による予備学習

続く実験：[OPENEDの表示保持・再発火抑制](0924-opening-temporal.md)。
0.75秒の表示保持と手の離れ・再準備確認を組み合わせた結果を別記しています。

2026-09-24。現ブランチで実施。本番の認識器・既定設定は変更していない。

## 結果と採否

中央マスク継続と学習器の組み合わせで、幕越しの action macro-F1 は **0.856**、幕なしは **0.857**。ラムネの動作区間・夕涼みの識別には改善余地がある。一方、開栓表示の再出現・未検出は残るため、本番への統合は見送る。OPENEDの注釈前後への連続した伸長は、ユーザー指定により正しい仕様として許容する。

数値はこの撮影セット内の予備評価であり、新しい人物・撮影日・照明での性能保証ではない。方式を比較する過程で画像と評価結果を確認しているため、方式探索全体を含む完全未使用テストでもない。

## データとラベルの意味

- 16動画・6,277フレーム。幕越し12本、幕なし4本。
- action: RAMUNE 9区間・706フレーム、RELAXING 11区間・1,731フレーム、NONE 3,840フレーム。扇ぎ・打ち水の正例はゼロ。
- phase: FORMING 146、READY 297、OPENED **29**、WAIT_RELEASE 157フレーム。各9区間。
- ユーザー確認に基づき、action未指定区間と空のcontrast3はNONEとする。
- フレーム番号は0始まり、区間終端を含む。動画SHA-256・総フレーム数を検証する。
- actionは準備・終了動作も含む。現行RAMUNE出力は開栓成功後の短い保持なので、action F1だけでは現行の成功判定能力を公平に表せない。
- この差を確認するため、現行のFORMING / READY / OPENED / WAIT_RELEASEをすべてRAMUNEに対応させた「状態展開」ベースラインも集計する。
- action内でphase未指定のフレームは不明としてphase学習・評価から除外。夕涼みphaseも未注釈のため除外。action外はphase NONE。評価対象はラムネ4段階＋NONEで、4動作すべてのphase評価ではない。

## 分割・モデル

幕越しは末尾のtake番号1/2/3をグループとし、同じ番号のboth・contrast・ramune・yusuzumiをまとめて評価側に回す3分割。各外側分割の学習動画だけを使い、内側のtake分割で設定を選ぶ。同一動画のフレームを学習側と評価側へ分散させない。幕なし4動画は設定選択に使わず、幕越し12動画で学習したモデルの条件間転移を測る。人物・撮影日を分けた検証ではない。

モデルはクラス頻度で重み付けしたridge分類器。肩・肘・手首・腰8点を胴体長で正規化し、座標とvisibility、過去窓の平均・標準偏差・差分を使う。未来フレーム・ファイル名・絶対時刻・正解phaseは特徴に含めない。現在骨格がないときはNONE。actionとphaseは独立に学習するため、時系列状態遷移や両出力の整合性は保証しない。

候補は履歴0.25 / 0.75秒、正則化0.01 / 0.1 / 1.0、線形 / 非線形（固定seed 924のsin・cosランダム特徴128次元）。標準化とクラス重みは各学習分割で計算し、12候補から内側macro-F1で選ぶ。追加依存なし。MediaPipe Lite VIDEOを元の全フレームで解析し、注釈と同じframe / fpsを時刻に使う。実カメラのフレーム落ち・推論速度は未検証。

中央マスクは既存SUBJECT_AREAの横範囲0.35〜0.75以外を灰色127に置換し、全フレームに適用する。この条件では人物選択を無効化する。マスク幅は学習せず固定。撮影位置が変わると腕などを隠す可能性がある。

## 開栓表示の仕様と再評価

ユーザーによる仕様の明確化を反映：**注釈した開栓点を含む連続したOPENEDは、注釈より前後に長くても正しい判定として扱う。いったん消えてから再び出る場合は改善対象。** 以前の「READYの71フレーム、WAIT_RELEASEの48フレームをOPENEDと誤認識」「開栓前90フレームを誤出力」という解釈は撤回する。注釈境界との不一致だけでは誤判定・再判定を意味しない。

元のtimeline.jsonは保存したまま、4条件の保存済み予測を再集計した。学習・モデル選択は旧来の厳密なフレームラベルに基づいたままであり、新仕様に合わせた再学習・再選択はまだ行っていない。従来のphase F1は旧注釈との一致度としてJSONに残すが、開栓表示の合否判断には使わない。

### 集計方法

- OPENEDの連続区間を作り、注釈のOPENED区間と重なれば対応づける。前後への伸長は減点しない。現在は点イベントがないため、既存の短いOPENED区間を基準として使う。
- 1フレームでもOPENEDが消えれば別区間。途切れの秒数も記録し、ちらつきと長い中断を後から区別できるようにする。
- 対応した区間の終了後から次の注釈RAMUNE動作の開始まで（次がなければ動画末尾まで）の再出現を記録する。別のRAMUNE試行を再判定扱いしない。
- 注釈と重ならない予測は「未対応」として残す。1フレームの境界ずれも自動的には許容せず、連続伸長と分けて確認する。
- 注釈を拾えていない場合も見逃さないよう、各RAMUNE動作開始から次のRAMUNE開始までの複数出力区間と再出力数を別に記録する。これは成功回数ではなく、表示の分断候補数である。

### 次の改善

1. OPENEDの継続長を注釈に合わせて短縮する対応は行わない。再出現・未対応・未検出を分けて優先順位を決める。
2. 短い欠落を許容する表示保持と、同じ試行内の再発火を防ぐ状態管理を個別に比較する。表示を滑らかにするだけで成功通知が複数送られないよう、通知回数も別に評価する。
3. 再試行の開始条件は、明確な手の離れ・新しい準備動作などで判断する。正解注釈を実行時の抑制条件には使わない。
4. 新仕様で学習器を選び直す場合は、学習側動画だけで保持・再解除の設定を選ぶ。評価側予測をそのまま正解ラベルとして学習へ戻さない。

  --output docs/0924-timeline-central-results.json

## 再現

gesture_detectionディレクトリで実行する。sharedの0924動画・timeline.jsonとLiteモデルが必要。

```bash
uv sync
OPENBLAS_NUM_THREADS=1 uv run python -m scripts.evaluate_timeline
OPENBLAS_NUM_THREADS=1 uv run python -m scripts.evaluate_timeline \
  --no-subject-selection --output docs/0924-timeline-raw-results.json
OPENBLAS_NUM_THREADS=1 uv run python -m scripts.evaluate_timeline \
  --no-subject-selection --central-mask --output docs/0924-timeline-central-results.json
OPENBLAS_NUM_THREADS=1 uv run python -m scripts.evaluate_timeline \
  --no-subject-selection --central-mask --linear-only \
  --output docs/0924-timeline-central-linear-results.json
uv run pytest --no-cov
uv run python -m compileall src
```

実行環境ではuv sync後に.venv/bin/pythonで実験した。骨格キャッシュとフレームごとの評価側予測はshared/results/0924-cacheに保存。キャッシュは動画・認識コード・モデル・入力条件で識別し、環境設定が変わった場合は新しい--cacheを指定する。JSONには動画・注釈ハッシュ、環境、各動画の成績、分割ごとの選択設定、混同行列を残す。

検証：追加7テスト、既存を含む全305テストが通過。TCPテスト1件はサンドボックスの通信制限で失敗したため、制限外で個別再実行して通過。変更ファイルのruffと構文検査も通過。実カメラ・Unity・マイコンへの接続は未実施。

## 次に改善する箇所

1. action分類の試作には中央マスク＋学習器を候補として残す。NONE区間の誤出力が残るため、この結果だけで本番に採用しない。
2. ラムネは注釈を含む連続OPENEDを許容し、いったん消えた後の再出現と未検出を改善する。表示の継続時間と成功通知の重複は分けて評価する。
3. 扇ぎ・打ち水、対象動作に似た通常動作、別人物・別撮影日のデータを追加し、固定した方式で新しい評価セットを測る。
