# 幕越し手動注釈による姿勢評価

## 目的

幕なしと同程度の所作認識精度に近づける前段として、幕越し映像で現在の姿勢推定器が
人物と関節を正しく捉えているかを手動注釈に対して測る。単にランドマークが返った割合を
成功とせず、位置が正しいか、被写体不在時に誤検出しないかも分けて評価する。

## データ

`shared/videos/bihind-the-screen_sabaku` の熟練使用者1名、4動作各3本を使用した。
各動画から均等に8フレーム、合計96フレームを抽出し、肩・手首・腰の6点を注釈した。

- 被写体あり: 62フレーム
- 被写体なし: 34フレーム
- 座標が確定した関節: 335点
- 座標を確定できない関節: 36点
- 被写体不在の関節: 205点

`aogi1_2-6/comment.txt` と `aogi2_2-5/comment.txt` に記録された旧表現は評価時に補正する。
`aogi1` の `uncertain` と `pending`、`aogi2` の `pending` は `absent` として扱う。
元CSVは来歴を保つため変更しない。

## 指標

- `pose_recall`: 被写体ありのフレームで姿勢が1件以上返った割合
- `false_positive_rate`: 被写体なしのフレームで姿勢が返った割合
- `point_detection_rate`: 座標注釈済み関節のうち、姿勢が返ったフレームに属する割合
- `PCK@0.2`: 推定誤差が手動注釈の肩幅（肩が使えない場合は腰幅）20%以内の関節割合。
  姿勢が返らなかった関節も失敗として分母に含める

位置誤差は、推定に成功した点だけを対象にした中央値も併記する。ただし誤った人物や幕の
輪郭を検出した場合にも数値が出るため、`PCK@0.2` と併せて判断する。

## 初回結果

MediaPipe Pose Lite / Fullを`IMAGE`モードで各注釈画像へ独立に適用した。

| 条件 | pose recall | 不在時誤検出率 | point detection |
|---|---:|---:|---:|
| Lite、無加工、閾値0.5 | 11.3% | 5.9% | 11.3% |
| Full、無加工、閾値0.5 | 3.2% | 0.0% | 3.6% |
| Lite、無加工、閾値0.2 | 51.6% | 32.4% | 54.3% |
| Full、無加工、閾値0.2 | 12.9% | 14.7% | 13.1% |

Lite・閾値0.5に既存の前処理を適用した結果は以下のとおり。

| 前処理 | pose recall | 不在時誤検出率 | point detection |
|---|---:|---:|---:|
| なし | 11.3% | 5.9% | 11.3% |
| 弱いぼかし | 14.5% | 5.9% | 15.2% |
| 50%縮小 | 14.5% | 2.9% | 14.0% |
| CLAHE | 37.1% | 17.6% | 38.8% |
| 50%縮小 + CLAHE | 27.4% | 14.7% | 25.7% |
| 中央マスク | 17.7% | 0.0% | 18.5% |
| 中央マスク + 50%縮小 | 19.4% | 2.9% | 18.8% |

無加工条件では、検出された点にも`PCK@0.2`を満たすものがなかった。ぼかしと縮小では
少数の正しい点が得られたが、全335点に対して約1%未満である。CLAHEや低閾値化は
「何かを検出する率」を上げる一方、不在時の誤検出を増やし、正しい関節位置にはならない。

したがって現データの範囲では、単純な前処理や閾値変更だけで幕なし相当へ近づける根拠は
ない。所作判定器の調整より前に、姿勢入力方式または撮影・投影条件を変更する必要がある。

## 次の検証

1. ファイル名の動作区間を正解として、幕あり・幕なしの所作再現率と誤発火率を同じ指標で測る。
2. 手動注釈に対してYOLO Poseなど別方式のPCKと不在時誤検出率を測る。
3. 追加撮影では幕なし・幕ありを同一カメラ位置、同一動作、可能なら同一タイミングで対にする。
4. 入力方式または撮影条件の候補が、幕なし基準に対する差を再現性をもって縮めるか確認する。

この評価は1名分であり、熟練使用者本人に対する結果である。方式選定には使えるが、利用者間の
一般化性能を保証するものではない。

## 動作区間による幕あり・幕なし比較

ファイル名の`[動作名][通し番号]_[開始秒]-[終了秒]`を正解区間として、現行Liteモデルを
両環境の各12本へ適用した。映像は同一人物・各動作3本であるが、幕ありと幕なしは別テイクで
あり、フレーム単位の対応関係はない。処理量を抑えつつ時系列判定を維持するため、元映像の
時刻を保ったまま約10 FPSで評価した。

| 環境 | 動作 | 動画単位の検出 | 動作区間の姿勢取得率 | 動作フレーム率 |
|---|---|---:|---:|---:|
| 幕越し | 扇ぎ | 0/3 | 11.3% | 0.0% |
| 幕越し | ラムネ | 0/3 | 48.6% | 0.0% |
| 幕越し | 夕涼み | 0/3 | 18.4% | 0.0% |
| 幕越し | 打ち水 | 0/3 | 5.6% | 0.0% |
| 幕なし | 扇ぎ | 2/3 | 99.5% | 34.4% |
| 幕なし | ラムネ | 0/3 | 100.0% | 0.0% |
| 幕なし | 夕涼み | 1/3 | 100.0% | 1.7% |
| 幕なし | 打ち水 | 1/3 | 100.0% | 7.4% |

ラムネは短い動作のため、10 FPSによる見逃しを除外する目的で6本だけ約30 FPSでも再評価した。
姿勢取得率は幕なし100%、幕越し50%だったが、ラムネ成立は両環境とも0/3のままだった。

この結果から問題を二段に分離できる。

1. 幕越しでは、まず姿勢入力が成立していない。動作判定閾値を調整しても解消しない。
2. 幕なしでは姿勢入力はほぼ完全だが、現行動作判定も4動作中3動作で再現率が不足している。

したがって「幕なしと同程度」を最終的な高精度とするには、幕越し入力だけを幕なしの現在値へ
合わせるのでは不十分である。先に幕なし動画で動作判定を再現可能にし、同じ判定器へ渡せる
品質の姿勢を幕越し側でも生成する、という順序で検証する。

再実行例：

```bash
uv run python -m scripts.evaluate_action_intervals \
  --output shared/results/action-intervals-lite.json

uv run python -m scripts.evaluate_action_intervals \
  --action RAMUNE \
  --sample-fps 30 \
  --output shared/results/action-intervals-ramune-30fps.json
```
