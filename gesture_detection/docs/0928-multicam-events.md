引き継ぎ：[main向けの成果・再現手順](0928-multicam-handoff.md)。
ラムネ・夕涼みはphase説明UIなしで実演されており、想定運用より難しい条件の診断結果。

カメラ別の入力と、打ち水・ラムネの解除／新しい準備を共有する候補で、
検出数を保ちながら打ち水の未対応イベントを22件から6件へ減らした。**

## 現行の評価基準

ユーザーからの訂正を反映した。

| 所作           | 試行の評価                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 打ち水・ラムネ | 正解action内で1イベント、表示は1区間。同じaction内の追加イベント・表示再出現は問題として数える |
| 扇ぎ・夕涼み   | action内に反応があれば検出。再出現だけでは不合格にしない。出力時間・他所作との取り違えは別集計 |

ラムネのphaseは従来どおりOPENED区間の前後1秒を許容する。
細かなphase境界を成立・解除の入力に使わず、注釈は採点時だけ参照する。
イベントの同一action内重複はphase許容幅とは独立に数える。

JSONの`detected`は反応の有無、`accepted`は上記の所作別基準を満たしたか。
扇ぎ・夕涼みの`accepted`は表示持続率が十分という意味ではない。
元の`reappearances`は診断値として残すが、減点する`penalized_reappearances`は
打ち水・ラムネに限定した。

前回レポートの「扇ぎ3/3のうち連続1/3」「夕涼みの再出現を不合格とする」という扱いは、
現行の採否基準には用いない。

## 1. 打ち水：肩・腰の推定変動だけで成立させない

既存判定は毎フレームの肩・腰を基準に手首の相対高さを計算する。
そのため、手首自体が動いていなくても胴体の推定位置が変われば、
「すくい上げ→振り下ろし」のような相対高さの変化が生じうる。
合成骨格の回帰テストでも、この条件で既存判定が発火することを再現した。
実動画の全誤反応がこの原因だったと断定するものではない。

`anchor`候補では既存判定の成立に加え、低い位置にあった時点の胴体高を固定基準にして、
**画像上でも手首が上昇・下降したこと**を要求した。
上昇量0.10胴体高・下降量0.15胴体高は既存値を使用し、
各動きが少なくとも0.08秒の観測をまたぐことを追加した。
単なる全身の移動をすくい上げにしないため、既存の相対高さ条件も残している。

| 入力             | カメラ  | 打ち水検出：前→後 | 未対応イベント：前→後 |
| ---------------- | ------- | ----------------: | --------------------: |
| 従来の人物選択   | camera1 |       **2/3→2/3** |               **2→0** |
| 全画面           | camera1 |           2/3→0/3 |                  23→4 |
| 全画面           | camera2 |       **2/3→2/3** |                   8→7 |
| カメラ別候補領域 | camera1 |           1/3→0/3 |                   3→0 |

全画面camera1などでは正しい試行も落ちるため、一律の改善ではない。
今回の統合候補では、以前の結果も踏まえ、camera1を従来の人物選択、camera2を全画面に固定した。
テイクや正解ラベルに応じて入力を切り替えたわけではない。
ただし、このデータを見ながら選んだ探索条件であり、独立した評価ではない。

## 2. 「一度発火したら、解除を見てから再許可」の問題

### 単独カメラだけで解除を確認する案

最初に次を試した。

- 成功後はそのイベントをロック。
- 手を下げる／ラムネの両手を離す姿勢を0.3秒観測したら再許可。
- 骨格欠落や時間経過だけでは再許可しない。
- 成功表示は打ち水0.35秒、ラムネ0.8秒に限定し、保持表示が再出現しないようにする。
- 扇ぎ・夕涼みにはロックを掛けない。

ところがcamera2の全画面入力では、元動画を2回つないだ際に、
検出済みの打ち水2試行・ラムネ2試行すべてで2回目が抑制された。
解除姿勢に必要な点が安定して見えないと、解除条件が成立しないためである。

両手ではなく、実際に発火した手（ラムネは押し込む上側の手）で解除を判定する案も試した。
ラムネ`001851`の2回目は回復したが、他の3試行は回復しなかった。
単に再発火数が減ったことを改善とは扱わず、これらの単独ロック案は採用しない。

### 解除はどちらの視点で見えてもよい

次に、統合側にイベントごとに1つのロックを置き、
**どちらかの新しい骨格で解除姿勢が見えればよい**方式を試した。
0.2秒より古い骨格を使わず、観測のない時間を解除の証拠にしない。

この方法で、camera2単独では見えなかった復帰を他方の視点から補える例があった。
ただし非対称入力の打ち水`001754`では、同じ動作に対する両カメラの通知時刻が離れ、
解除後にもう片方の古い動作の通知を受け付けてしまい、重複が残った。

### 解除後に始まった新しい準備だけを受け付ける

最終候補では、解除の観測に加え、イベントを出した検出器が持つ準備開始時刻を確認した。

```text
初回イベント → ロック
            → どちらかのカメラで解除姿勢を観測
            → その解除より後に始まった準備からのイベントだけを許可
```

打ち水ではREADYへ入った時刻、ラムネではFORMINGへ入った時刻を記録する。
注釈のphase開始時刻ではなく、認識器自身の状態遷移の時刻を使う。
遅れて届いた古い準備に由来する通知を、新しい動作として受け付けない。

これにより非対称入力で残っていた打ち水の同一action内重複が1件から0件になった。
同一action内の表示再出現も0になり、検出3/3を維持した。

## 3. 統合条件の比較

全条件で、前回有望だったラムネ準備追従`follow_peak`を使用した。
以下はcamera1由来の注釈時計での集計。

| 統合条件                                     | 打ち水の検出 | 重複・再出現なしの打ち水 |  ラムネ | 打ち水未対応イベント |
| -------------------------------------------- | -----------: | -----------------------: | ------: | -------------------: |
| 両方全画面、前回方式                         |          3/3 |                      3/3 |     2/3 |                   22 |
| 両方全画面＋anchor                           |          2/3 |                      2/3 |     2/3 |                   11 |
| 非対称入力のみ                               |          3/3 |                      2/3 |     2/3 |                   11 |
| 非対称入力＋anchor                           |          3/3 |                      2/3 |     2/3 |                    8 |
| 非対称入力＋anchor＋解除共有                 |          3/3 |                      2/3 |     2/3 |                    7 |
| **非対称入力＋anchor＋解除共有＋新しい準備** |      **3/3** |                  **3/3** | **2/3** |                **6** |

非対称入力：camera1=`rules_subject`、camera2=`rules_full`。
解除共有には、発火した手の観測を使った。
入力の変更・anchorの追加・再許可制御の効果が混在するので、
22→6の全改善をロック機構だけの効果とは解釈しない。

残る6件は打ち水であり、ラムネの未対応イベントは0。
すべて未注釈領域というわけではなく、別のaction中の打ち水表示も約0.37秒ある。
したがって、今回の候補も誤反応の問題が解決したとはいえない。

## 4. 正当な再試行を止めないか

元の全フレーム列を2回連結し、準備・復帰も含めて連続再生した。
途中で認識器・統合器・ロックをリセットしない。

最終候補の結果：

| テイク   | 所作   | 1回目     | 2回目     |
| -------- | ------ | --------- | --------- |
| `001754` | 打ち水 | 1イベント | 1イベント |
| `001807` | 打ち水 | 1イベント | 1イベント |
| `001817` | 打ち水 | 1イベント | 1イベント |
| `001839` | ラムネ | 1イベント | 1イベント |
| `001851` | ラムネ | 1イベント | 1イベント |
| `001828` | ラムネ | 見逃し    | 見逃し    |

この確認により、単独カメラのロックで見つかった「一度検出したら二度と解除されない」
問題が、最終候補の検出済み5試行では再現しないことを確認した。
数秒以内に素早く2回行う実演や、異なる動作への切り替わりを網羅した試験ではない。

なお、両方全画面＋新しい準備を要求する条件では`001754`の2回目が抑制された。
解除・準備の観測に使う入力条件は依然重要であり、どの入力でも解決する方式ではない。

## 5. 扇ぎ・夕涼みの現状

再検出を許容して集計し直したので、扇ぎは最終候補で3/3試行を検出として数える。
camera1注釈時計で、準備も含むaction内の表示率の試行平均は約76.8%。
他所作中の誤った扇ぎ表示が約2.07秒あるため、再検出とは別に取り違えの課題が残る。

夕涼みは1/3試行で反応するが、action内表示率の試行平均は約2.1%
（camera2注釈時計では約1.5%）と低い。
再検出を禁止しなくても、2試行を見逃しており、観測できている静止状態が少ない。
今回の変更はイベント所作を中心にしたもので、夕涼みの認識不足は残っている。

## 採否と今後の焦点

- 所作別の評価基準を現行基準とする。扇ぎ・夕涼みには一回限りのロックを適用しない。
- camera1従来人物選択＋camera2全画面、anchor、解除共有、新準備確認の組み合わせを次の比較候補とする。
- 単独カメラの解除ロックや、両カメラへ同じ入力・追加条件を一律適用する方式は採用しない。
- 残る打ち水6件は今後の診断候補。ラムネ`001828`と夕涼みの追加改善は、
  phase説明UIなしの実演条件が判明したため一旦保留し、mainへの成果共有を優先する。

配置・素材は固定のまま。今回の値は同じ撮影データ上の探索結果であり、
独立した素材やライブ動作での性能保証ではない。
2カメラ間の取得時刻は均等取得近似なので、準備・解除の時刻比較の頑健性も今後の確認対象となる。
