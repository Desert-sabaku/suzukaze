# アーキテクチャ

## 構成

- `modules/app.py`: 入力ループ、ワーカーの生存期間、描画と保存
- `modules/pose_worker.py`: MediaPipe 推論、時系列ジェスチャー状態
- `modules/relaxing.py`: 入力元時刻による静止判定
- `modules/uchimizu.py`: すくい上げと振り下ろしの状態機械
- `modules/ramune.py`: 両手の準備と押下の状態機械
- `modules/rendering.py`: OpenCV 描画
- `modules/config.py`: パス、入力設定、しきい値
- `modules/ipc.py`: 最新フレームを共有するメールボックス
- `modules/video_output.py`: 動画書き出し用の有界バッファ
- `modules/yolo_worker.py`: 未使用の旧物体検出ワーカー

通常のアプリケーションは MediaPipe のみを起動します。YOLO モデルは実行に不要です。
MediaPipe の Lite モデルがない場合は自動取得します。

## 設定と入力

`.env.example` を `.env` にコピーして設定します。既存の環境変数を優先し、`.env` は
作業ディレクトリにかかわらずプロジェクトルートから読みます。相対パスもプロジェクト
ルートを基準に解決し、絶対パスと `~` も使用できます。

`VIDEO_SOURCE` が空なら `CAMERA_INDEX` のカメラを使用します。動画を使う例は次のとおりです。

```dotenv
VIDEO_SOURCE="sample_movies/sample.mp4"
```

`CAMERA_BACKEND=0` は OpenCV の自動選択、Linux の V4L2 は `200` です。モデル、FPS、
FourCC、出力バッファなどの全設定は `.env.example` を参照してください。

## 出力

動画入力は終端で終了します。注釈付き映像を `VIDEO_OUTPUT_PATH` に保存し、未指定なら
`OUTPUT_DIR` 以下に入力名と実行時刻を含む `.output.mp4` を作ります。音声は保存しません。

書き出しは別スレッドで行い、既定で8フレームの有界バッファを使います。満杯の場合は
フレームを捨てずに待機します。`Esc` 終了時も受理済みフレームを順番に保存するため、
終了処理が待つ場合があります。1080×720のBGR画像8枚なら、処理中の画像を除いて
約18 MiBです。

## フレーム識別子と時刻

読み取りに成功した全フレームへ、0始まりの `frame_id` を付けます。カメラで推論を省略
されたフレームも番号に含みます。画像、`frame_id`、`timestamp` は同じロック内で共有し、
Pose の結果は人物が見つからない場合も入力値をそのまま返します。

- 動画: `CAP_PROP_POS_MSEC` による入力動画内の秒数
- カメラ: 取得直後の単調増加時計による秒数

壁時計の日付や推論完了時刻ではありません。動画位置が不正または増加しない場合は、入力
FPS（取得値が不正なら設定 `FPS`）の1フレーム分だけ進めます。周波数、保持時間、
クールダウンはすべてこの入力元時刻で計算するため、処理速度には依存しません。

MediaPipe の VIDEO モードには秒を整数ミリ秒へ変換して渡します。異なる入力時刻が同じ
整数ミリ秒になる場合に限り、MediaPipe 用の値だけを直前値+1以上にします。判定時刻と
返却メタデータは元の秒数を保持します。負、非有限、同値、逆行する時刻は VIDEO モードで
拒否します。入力を途中でシーク・再開する場合は新しい解析器が必要です。

## 動画とカメラの処理差

動画は各フレームの推論完了を待ち、同じ `frame_id` と `timestamp` の結果だけを描画・保存
してから次へ進みます。同時に処理中となるのは1枚だけで、終端の最終フレームも保存します。
推論中に `Esc` を押した場合、その未完了フレームは保存しません。ワーカーが停止した場合は
古い結果を使わず、エラーとして終了します。実時間の再生速度には合わせません。

カメラは最新フレーム優先で、中間フレームを省略する場合があります。表示には最新の利用
可能な推論結果を重ねるため、結果が対応する元画像より新しい画像へ表示されることがあります。
メタデータは実際に解析した古いフレームを示します。

## MediaPipe の実行モード

既定は `POSE_RUNNING_MODE=VIDEO` で、同期的な `detect_for_video` と時間追跡を使います。
`IMAGE` は各画像を独立に `detect` します。どちらもアプリケーション側の状態機械を保持し、
VIDEO モードも非同期コールバックや動画フレームの欠落を導入しません。姿勢欠落時は
アプリケーションのジェスチャー履歴をリセットしますが、MediaPipe の時計は巻き戻しません。

モードの比較結果と現在の採用理由は[過去の評価](evaluations.md)を参照してください。
