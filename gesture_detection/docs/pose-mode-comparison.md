# IMAGE / VIDEO モード比較（2026-09-17）

## 結論

追加の手動確認を経て、現在は追跡挙動を理由に `VIDEO` を既定としています。`IMAGE` は
比較用に残します。以下の初回評価では `IMAGE` 維持を提案していましたが、これは過去の
判断です。また、正解区間がないため、下表は分類器の出力数であり認識精度ではありません。
ラムネ動画は旧仕様の動作なので、現在のラムネ認識評価にも使えません。

生データは [pose-mode-comparison.json](pose-mode-comparison.json) です。

## 方法

- Python 3.12.3、MediaPipe 0.10.35、OpenCV 5.0.0、設定FPS 30
- LiteモデルのSHA-256: `59929e1d1ee95287735ddd833b19cf4ac46d29bc7afddbbf6753c459690d574a`
- 同じ実行機で3動画を元解像度のまま全フレーム処理
- 動画・モードごとに新しい解析器を作り、IMAGE、VIDEOの順で各1回実行
- デコードと保存を除く `process()` の時間、姿勢の有無、選択動作、遷移時刻を記録
- 全6,238回で返却された `frame_id` と `timestamp` が入力と一致

## 結果

| 動画 | モード | フレーム / 姿勢あり | 処理秒 | 扇ぎ | 打ち水 | ラムネ |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| kohara_fanning_01 | IMAGE | 1495 / 1479 | 137.636 | 490 | 0 | 0 |
| kohara_fanning_01 | VIDEO | 1495 / 1495 | 117.375 | 196 | 0 | 0 |
| kohara_ramune_01 | IMAGE | 924 / 924 | 187.496 | 39 | 144 | 0 |
| kohara_ramune_01 | VIDEO | 924 / 924 | 42.103 | 59 | 80 | 0 |
| kohara_uchimizu_01 | IMAGE | 700 / 700 | 48.630 | 0 | 79 | 0 |
| kohara_uchimizu_01 | VIDEO | 700 / 700 | 30.255 | 3 | 33 | 0 |

扇ぎの最初の成立は両モードとも3.930秒でしたが、成立フレーム数は大きく異なりました。
打ち水もIMAGEは6区間、VIDEOは3区間となり、VIDEOでは扇ぎが3フレーム出ました。
いずれも正解区間がないため、どちらが正しいかは判断できません。処理時間も単一実行で、
順序、キャッシュ、負荷を統制していないため、一般的な高速化の根拠にはしません。

## パイプライン上の確認

VIDEOは増加するミリ秒時刻を受理し、元の入力IDと秒時刻を維持しました。この試験は
GUIとIPCを経由していません。カメラのフレーム省略と表示遅延は最新フレーム方式の性質で、
VIDEOモードでも解消しません。MediaPipeへ渡す整数ミリ秒だけが量子化衝突時に1 ms進み、
判定時刻は元の入力元時刻を使います。

今後モードを再評価する場合は、[手動テスト](manual-testing.md)の手順で正解区間を付与し、
同一フレームIDにおける誤検出、見逃し、成立・解除、軌跡を比較します。
